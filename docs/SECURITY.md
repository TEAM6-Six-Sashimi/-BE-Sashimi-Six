## 인증 모델

Stateless JWT Bearer 토큰 (세션 쿠키 아님). 로그인 시 발급된 액세스 토큰에 버전 번호를 함께
심고, Redis에 사용자별 현재 버전을 저장(`TokenVersionService`). 비밀번호 변경·재로그인 시
버전을 올리면 이전 토큰은 즉시 무효화됨 — 서버가 세션을 들고 있지 않아도 강제 로그아웃 가능.

## CSRF 비활성화 근거

모든 API가 `csrf().disable()`. CSRF는 브라우저가 **자동으로** 인증정보(쿠키)를 실어 보내야
성립하는데, 이 서비스는 `Authorization: Bearer` 헤더 기반이라 공격자 페이지가 그 헤더를 강제로
실을 방법이 없음 — CSRF의 전제조건 자체가 성립하지 않음.

**잔여 리스크**: `JwtTokenProvider.resolveToken()`은 Authorization 헤더가 없을 때 `accessToken`
쿠키도 인증 수단으로 허용함. 현재는 프론트/백엔드가 다른 도메인이라 쿠키가 자동 전송되지 않아
안전하지만, 향후 동일 도메인으로 통합 배포 시 "CSRF 비활성화 + 쿠키 인증 허용" 조합이 실질적
CSRF 벡터가 될 수 있음 — 도메인 통합 시 재검토 필요.

## Redis 장애 시 fail-open / fail-closed 비대칭 설계

Redis 의존 보안 체크의 장애 시 동작은 통일돼 있지 않으며, 이는 의도적 설계입니다 — "잘못
통과됐을 때"와 "잘못 막았을 때" 중 어느 쪽 피해가 큰지를 기준으로 나눔.

| 구성요소 | Redis 장애 시 | 근거 |
|---|---|---|
| Rate Limiter / 로그인 방어 (`RateLimiterService`, `LoginProtectionService`) | fail-open | 속도 제한은 2차 방어선. 잘못 통과시켜도 최악은 무차별 대입이 약간 더 허용되는 정도 — 서비스 전체 로그인 불능보다 나음 |
| JWT 인증(블랙리스트·버전 체크) (`JwtAuthenticationFilter`) | fail-closed | 실패한 채로 통과시키면 로그아웃되었거나 탈취된 토큰이 그대로 인증됨 — 가용성보다 보안 우선 |
| **점검모드** (`MaintenanceModeService`, 신규) | fail-open | 점검모드는 부차적 접근 제어라, Redis 장애로 점검모드 상태를 못 읽으면 "점검모드 꺼진 것"으로 간주 — 불필요하게 서비스 전체를 막는 것 방지 |

## 로그인 방어 계층 (2026-07-12)

기존 계정당 5분/5회 시도 제한만으로는 같은 IP가 여러 계정에 흔한 비밀번호를 1~2번씩만
시도하는 크리덴셜 스프레이를 못 잡는다는 걸 확인하고 추가:

- **IP 스프레이 탐지** — 5분 내 서로 다른 계정 3개 이상 실패 시 해당 IP 30분 차단
- **반복 위반 에스컬레이션** — 같은 계정이 24시간 내 재차 걸리면 5분 → 30분 → 1일로 잠금 시간 증가
- **이상 로그인 이메일 알림** — 2차 위반부터 계정 소유자에게 안내
- **Grafana 상대적 급증 알림** — 고정 숫자가 아니라 최근 1시간 평균 대비 3배 이상일 때만 발동

임계값은 실제 공격 로그가 없는 베타 단계라, 로그 볼륨 분석 대신 사람이 물리적으로 할 수 있는
행동의 한계와 서비스 자체 트래픽 대비 상대값을 근거로 정함.

## CI/CD 파이프라인 보안 (2026-07-15 추가)

- 점검모드 자동 연동에 쓰이는 관리자 계정(`admin08`)은 CI 전용으로 분리, 사람이 쓰는
  계정(`admin01~07`)과 완전히 격리 — 자동화 로그인이 팀원 세션을 끊는 부작용 방지
- CI에서 발급받은 토큰은 `::add-mask::`로 Actions 로그에 절대 노출되지 않으며, 워크플로우
  스텝 간에도 전달하지 않고 각 스텝이 독립적으로 로그인 — 토큰 유출 표면 최소화
- 관리자 계정 비밀번호는 현재 전 계정 동일(`admin`) — 베타/캡스톤 단계의 의도적 트레이드오프
  (팀 내부 테스트 편의 우선). 실 운영 전환 시 계정별 고유 비밀번호로 교체 필요

## 기타 기본기

- 비밀번호는 BCrypt로 해싱 저장 (평문·역가능 암호화 없음)
- 업로드 파일은 확장자가 아니라 매직바이트로 실제 형식 검증(`FileSignatureValidator`)
- 관리자 전용 API는 `ROLE_ADMIN`으로 분리, `/actuator/prometheus`는 내부 IP 대역 +
  관리자 권한만 접근 허용

## 알려진 미해결 항목

- CSP(Content-Security-Policy) 헤더 — S3/CloudFront, API 도메인 등 실제 로딩 리소스 정리 후
  신중하게 별도 작업 필요 (의도적 보류)
- 강의 상세 페이지 `?sub=` 파라미터 관련 잠재적 XSS 알림 — evidence 비어있어 신뢰도 낮음,
  수동 확인 필요
